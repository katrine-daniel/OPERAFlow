# External credentials

Nothing below is configured yet. Each integration stays **DISABLED** or clearly labelled **DEMO / MANUAL**
until its credentials are supplied and a connection test passes. No integration reports success without a real call.

| Needed for | Credential | Where it comes from | Phase |
|---|---|---|---|
| Core | `ENCRYPTION_KEY` (32-byte base64) | Generate locally; store in your secret manager | 1 ✅ |
| Core | PostgreSQL password | Your DB / generated for compose | 1 ✅ |
| Booking website sync | API base URL + API key/OAuth client **for an authorised sandbox and production** | Booking-website vendor / your dev team | 2 |
| Booking website webhooks | Signing secret: **generated by OPERAFlow** (Booking sources page) and given to the website operator together with `docs/WEBHOOK.md` | Your admin → website operator | 2 ✅ ready |
| TBO bookings | TBO API credentials **only if** your TBO contract grants API access. Otherwise the labelled manual/CSV adapter is used | TBO account manager | 2 |
| Report email delivery | Microsoft Graph `Mail.Send` (application or delegated) **or** Gmail API send scope, or SMTP relay credentials | M365 / Google Workspace admin | 3 |
| Ops group delivery | Microsoft Teams incoming webhook / Slack webhook (only supported, authorised channels) | Teams/Slack admin | 3 |
| Supplier follow-ups (Microsoft 365) | Entra ID app registration: tenant ID, client ID, client secret; scopes `Mail.ReadWrite`, `Mail.Send`, `offline_access`; admin consent | M365 admin | 4 |
| Supplier follow-ups (Gmail) | Google Cloud OAuth client (web); scopes `gmail.modify`, `gmail.send`; OAuth consent screen (internal) | Google Workspace admin | 4 |
| Booking-site tests | Sandbox base URL, sandbox test accounts, test payment method from the payment provider's test mode | Booking-website vendor | 5 |
| Monitoring (optional) | Sentry DSN or equivalent | Your tooling | 6 |
